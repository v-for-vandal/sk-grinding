# Sub-skill requirements and edits on existing perks

- **Status:** chosen (globals + runtime injection by the DLL); details to confirm in R-25.
- **Design:** design-v2 §5.6, Q-DYN-10 (decided: `current` is checked), Q-DYN-11 (decided: a
  bought perk stops working below the requirement), Q-DYN-12 (showing requirements), Q-DYN-13 (decided:
  this block); per-skill verdicts in `skills/<skill>/perks*.md` (*Sub-skill requirements*),
  e.g. [`skills/block/perks.md`](../skills/block/perks.md). Background:
  [`refs/perk-requirements.md`](../refs/perk-requirements.md).
- **Depends on:** [*subskill-state*](subskill-state.md); our ESL with the globals.
- **Research:** [R-25](../research/R-25-perk-condition-injection.md).

## What it does

For perks of LoreRim / Requiem / Ordinator listed in config, without overriding their records:

1. **Requires** (purchase): add, replace or remove skill-level conditions in the perk's own
   conditions (`BGSPerk::perkConditions`). Evaluated only in the perks menu, for the player.
2. **Records** (effects): add the same requirement to the perk's entry points, so a bought perk
   stops working while the requirement is not met (Q-DYN-11; on by default, a perk can be
   exempted in config).
3. **Abilities given by the perk** (records "ability *X*"): add the requirement to the conditions
   of the spell's effects, because an ability entry has no conditions of its own.
4. **Numbers:** change magnitudes of entry points and of abilities / spells / magic effects the
   perk uses (e.g. `+25%` → `+15%`).

Not done here: adding or removing entry points of an existing perk, new spells or new perks.
New perks (automatic sub-skill perks, Quick Reflexes) live in our ESL. If an existing perk must
be rebuilt structurally, the fallback is an ESL with overrides generated by a Mutagen patcher at
build time for the pinned LoreRim version (not Synthesis on the user's machine).

### One global per requirement

Each perk requirement from config (any formula: `bash >= 25`,
`oneOf(heavy-shield, light-shield) >= 50`, `threeOf(1h-*) >= 10 OR twoOf(1h-*) >= 20 OR
oneOf(1h-*) >= 30`, combined with AND / OR) gets **one** `GlobalVariable` in our ESL, e.g.
`SPO_Req_BLK07`, value 1 when met and 0 otherwise. The DLL computes the formula:

- the value read is the sub-skill's `current` (Q-DYN-10);
- hysteresis: once 1, the global goes back to 0 only below `threshold − hysteresis` (§5.6);
- when: on every change of a referenced sub-skill, on game load and when the perks menu opens
  (decay is applied lazily).

So conditions in records are always one simple test, and k-of-n formulas need no condition
tricks.

### Conditions added

- **Requires:** `GetGlobalValue SPO_Req_X == 1`, AND with the rest. Replacing `Block >= N`
  changes the comparison value of the existing `GetBaseActorValue Block` item; "drop" removes it.
- **Records and abilities:** NPCs have the same perks and abilities (Requiem gives them perks),
  so the condition must not touch them:
  `GetIsReference Player == 0 OR GetGlobalValue SPO_Req_X == 1`, added to the **perk owner**
  tab of each entry point, and to each effect of the ability spell.
- **OR precedence:** in Skyrim consecutive OR items form one group and groups are ANDed. The
  pair is appended at the end of the list, and the last existing item must have the AND flag
  (set it if it has a stray OR), otherwise the pair merges with it.

Ability effects with conditions are re-checked by the engine about once a second: the effect
turns off with a short delay. Entry points that fire on an event (hit, swing, bash) check at
the event.

## Variants

- **Chosen: runtime injection at `kDataLoaded`** from config. No record overrides; survives LoreRim
  updates of the perk; data-driven. Not visible in xEdit / CK; needs correct construction of
  condition items (R-25).
- Rejected: ESP overrides of the perks (conflicts with LoreRim patches, break on updates);
  Synthesis on the user's machine (extra step for a Wabbajack list); AVG extra values instead of
  globals (only if R-18 succeeds, see design-v2 Q-DYN-13).

## Config

Table per perk (perk FormKey or EditorID):

- `requires_add`: requirement formula (→ one global);
- `requires_replace`: `Block >= 75` → `Block >= 50` / drop;
- `effects_gated`: true / false (Q-DYN-11; default true from the global setting);
- `magnitudes`: entry point or effect → new value.

Global settings: `hysteresis` (§5.6), default `effects_gated` (true).

## Test

- Perks menu: a perk with an unmet requirement cannot be bought; with the requirement met it
  can; a replaced `Block` level shows the new number (R-25 check 4).
- Buy a gated perk, lower the sub-skill by console below `threshold − hysteresis`: its entry
  point stops (e.g. damage bonus gone), its ability effect turns off within ~1 s; raise it back:
  both return.
- An NPC with the same perk (Requiem NPC with Block perks) keeps the effects at all times.
- Condition dump after `kDataLoaded` for one perk of each kind: the OR pair is at the end, the
  item before it has the AND flag.
